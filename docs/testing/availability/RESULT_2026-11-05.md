## Deployment, announcement and method

The actual temporary URL was `https://vincent-expansion-acrobat-actors.trycloudflare.com`.
It served the compiled application/API with DEBUG=0, PostgreSQL 16, two Gunicorn
workers, secure-cookie/proxy settings and an expiry worker on a GitHub-hosted Linux
runner. All records were synthetic and fixture passwords were disabled before
exposure. SMTP was deferred; no notification scheduler or real-email delivery ran.

Source: `216fd043df0ff91b3be8c5f6a9f5755138014133`.
[Workflow run, attempt 2](https://github.com/chiranthanv/online-exam-portal/actions/runs/41967642824/attempts/2)
completed successfully. The generated URL and exact future window were published
in GitHub deployment **7566452264** before start; SCRUM-31 had a pre-announcement
and the resolved UTC/IST times were copied there before the window began.

The probe ran on the authorized Windows workstation outside the hosting runner,
using the existing monitor with TLS certificate/hostname verification, redirect
rejection, five-second slots and a three-second per-socket timeout. Observed control-
plane clock offset was 0.199 seconds. No maintenance exclusions were used.

Fixed five-second guards were declared before execution. The continuous raw run
started at **06:03:18.005475 UTC**, ended at **06:33:28.016329 UTC**, elapsed

## Workload and limits

Two hundred logically active synthetic API students completed 60 periodic
save/resume cycles: **24,200 requests, zero recorded errors**. Load reached the
origin over loopback with trusted-proxy headers, using 20 request workers; it
excludes external tunnel/TLS costs and is not 200 simultaneous full browsers.
The application permitted 60-minute attempts; this announced observation covers
the specified 30-minute interval of active exam work, not every allowed attempt
minute, warm-up or complete submit/expiry lifecycle.

The earlier first staging attempt had workload evidence but no external probe;
it is not counted as availability acceptance. The result above uses only attempt 2
and its single continuous external run. The endpoint was retired after the bounded
test and deployment marked inactive. It is not maintained public hosting.

Cloudflare Quick Tunnels are [development/test infrastructure without an uptime guarantee](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).
This measurement establishes only the declared sampled controlled-window result;
it does not establish production representativeness, future exam availability,
full WAN capacity or semester-long reliability. Per-socket/DNS timeout limits
remain those in the [monitor guide](README.md).
