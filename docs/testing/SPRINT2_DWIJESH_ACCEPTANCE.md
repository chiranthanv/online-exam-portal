## Implementation already integrated

- **Attempt/session (SCRUM-22 / OEP-F-014):** Dwijesh PR #35 supplies unique exam/student attempt creation, durable attempt state and session UUID binding. Current main also has #36 terminal response integrity and lead lock-scope work from #42. The backend checks the authenticated student, attempt ownership and matching session. Conflicting sessions are rejected. The current ExamAttempt / AttemptAnswer model and per-attempt lock scope are retained; no legacy Attempt model is reintroduced.
- **Autosave/recovery (SCRUM-23 / OEP-F-015):** answers are sent when the student selects or clears an option. The UI distinguishes saving, server-confirmed last-saved time, pending-to-sync and failure states. Transient failures are retried for at most three attempts, with 250ms then 500ms waits; reconnect and visibility events trigger queued sync. The queue is compared against the latest local selection before a response can clear it; submit is blocked while saves remain unconfirmed. The queue and attempt/session reference are held in sessionStorage, so this supports same-tab refresh and the tested reconnect flow, but does not establish guaranteed recovery after a browser/profile is permanently closed. The current queue has no persisted age timestamp, and no explicit browser-restart/crash or recovered-state-age test is recorded. A disconnected client cannot meet the ten-second server-persistence target; the UI reports pending state instead of claiming saved.
- **Timer/submission (SCRUM-24 / OEP-F-016):** the server sends deadline_at and server_now. The browser derives a monotonic deadline from their difference and performance.now(); the correction from #38 and regression coverage from #39 are retained. The Compose expiry worker polls at a one-second interval and marks expired in-progress attempts AUTO_SUBMITTED even when no browser request occurs. Manual submit is idempotent; late answer writes are rejected and terminal answers/timestamps remain immutable. A backend worker test calls expiry without a browser request. This branch adds a browser regression that moves the page's wall clock forward while an attempt remains open and verifies the monotonic countdown does not expire early; its CI result is pending.
- **Responsive/accessibility UI (SCRUM-32 / OEP-NF-005):** Dwijesh PR #46 was merged into Harkirat's current-schema integration in #43 and then into main. It contains the sticky countdown, corrected footer/navigation colors, 44px mobile interaction targets, keyboard/skip-link and radio-group checks, offline queue/reconnect/refresh coverage, and the submit-pending guard. The sticky timer test checks 1440x900, 390x844 and 320x844 viewports without horizontal overflow.

## Acceptance still open

1. **SCRUM-22:** implementation and PostgreSQL concurrency evidence are present. Independent integrated-flow acceptance/review remains necessary.
2. **SCRUM-23:** refresh/reconnect/retry are tested. A durable browser-restart/crash guarantee and recovered-state-age metadata/test are not evidenced; the sessionStorage scope is a known limit.
3. **SCRUM-24:** server deadline, expiry worker, manual submit, closed-write rejection and monotonic clock implementation exist. The new wall-clock browser regression is awaiting CI. The worker test simulates expiry without a browser request; a controlled deployed worker/closed-browser acceptance run remains useful.
4. **SCRUM-32:** automated contrast/keyboard/mobile/timer checks exist and the historical baseline is retained. A fresh Lighthouse run on the post-fix main UI and manual WCAG 2.1 AA checks remain required: full keyboard workflow/focus order, screen reader announcements, 200%/400% zoom, forced-colors/high-contrast mode and manual review of every error/confirmation/expiry state. The 30-Oct score is not reused as a post-fix score. The mobile 44px target-size check is additional WCAG 2.2 guidance; it is not substituted for the WCAG 2.1 AA criterion.

No story is marked Done by this evidence update. SCRUM-22 remains In Review; SCRUM-23, SCRUM-24 and SCRUM-32 remain In Progress pending the acceptance gaps above.
