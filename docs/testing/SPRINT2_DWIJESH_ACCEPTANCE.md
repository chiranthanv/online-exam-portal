## Implementation already integrated

- **Attempt/session (SCRUM-22 / OEP-F-014):** Dwijesh PR #35 supplies unique exam/student attempt creation, durable attempt state and session UUID binding. Current main also has #36 terminal response integrity and lead lock-scope work from #42. The backend checks the authenticated student, attempt ownership and matching session. Conflicting sessions are rejected. The current ExamAttempt / AttemptAnswer model and per-attempt lock scope are retained; no legacy Attempt model is reintroduced.
- **Autosave/recovery (SCRUM-23 / OEP-F-015):** answers are sent when the student selects or clears an option. The UI distinguishes saving, server-confirmed last-saved time, pending-to-sync and failure states. Transient failures are retried for at most three attempts, with 250ms then 500ms waits; reconnect and visibility events trigger queued sync. The queue is compared against the latest local selection before a response can clear it; submit is blocked while saves remain unconfirmed. The queue and attempt/session reference are held in sessionStorage, so this supports same-tab refresh and the tested reconnect flow, but does not establish guaranteed recovery after a browser/profile is permanently closed. The current queue has no persisted age timestamp, and no explicit browser-restart/crash or recovered-state-age test is recorded. A disconnected client cannot meet the ten-second server-persistence target; the UI reports pending state instead of claiming saved.
- **Timer/submission (SCRUM-24 / OEP-F-016):** the server sends deadline_at and server_now. The browser derives a monotonic deadline from their difference and performance.now(); the correction from #38 and regression coverage from #39 are retained. The Compose expiry worker polls at a one-second interval and marks expired in-progress attempts AUTO_SUBMITTED even when no browser request occurs. Manual submit is idempotent; late answer writes are rejected and terminal answers/timestamps remain immutable. A backend worker test calls expiry without a browser request. Dwijesh PR #50 adds a browser regression that advances the page wall clock by 24 hours, asserts the attempt remains open and no submit request is sent, restores the wall clock, then verifies the monotonic countdown continues decreasing. The test passed in the PR's 7/7 Playwright E2E run and the subsequent post-merge main browser run.
- **Responsive/accessibility UI (SCRUM-32 / OEP-NF-005):** Dwijesh PR #46 was merged into Harkirat's current-schema integration in #43 and then into main. It contains the sticky countdown, corrected footer/navigation colors, 44px mobile interaction targets, keyboard/skip-link and radio-group checks, offline queue/reconnect/refresh coverage, and the submit-pending guard. The sticky timer test checks 1440x900, 390x844 and 320x844 viewports without horizontal overflow. The authenticated CI audit on current main (Chrome 156, disposable SQLite, seeded synthetic student, 5-question demo attempt) scored 100/100 at 1440px, 390px and 320px; all scripted WCAG 2.0/2.1 A/AA, skip-link, labelled-radio, no-overflow and sticky-timer-at-bottom checks passed. This does not replace manual screen-reader, complete keyboard, browser zoom or forced-colors acceptance.
